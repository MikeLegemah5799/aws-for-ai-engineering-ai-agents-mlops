Use Converse, not InvokeModel

One request shape across model families, native tool use, guardrails and caching. Drop to InvokeModel only for embeddings, image models or provider-specific features.

Gate on evals, not vibes

Every prompt, model, knowledge-base or tool-schema change runs an offline eval in CI. A blocking gate is cheaper than a customer finding the regression.

Tag and log from day one

Application inference profiles with cost tags, invocation logging to KMS-encrypted S3, and alarms on throttles. Retrofitting attribution is painful.

converse.py
import boto3
from botocore.config import Config

brt = boto3.client(
    "bedrock-runtime", region_name="us-east-1",
    config=Config(retries={"max_attempts": 8, "mode": "adaptive"},
                  read_timeout=300, connect_timeout=5),
)
MODEL = "us.anthropic.claude-sonnet-4-5-20250929-v1:0"   # inference profile ID

# --- Converse (sync) ---
r = brt.converse(
    modelId=MODEL,
    system=[{"text": "You are a precise assistant. Answer in JSON."}],
    messages=[{"role": "user", "content": [{"text": "Summarize SQS vs SNS."}]}],
    inferenceConfig={"maxTokens": 800, "temperature": 0.2, "topP": 0.9,
                     "stopSequences": ["END"]},
    additionalModelRequestFields={"top_k": 40},       # provider-specific
    guardrailConfig={"guardrailIdentifier": "gr-abc123",
                     "guardrailVersion": "3", "trace": "enabled"},
)
print(r["output"]["message"]["content"][0]["text"])
print(r["usage"], r["metrics"]["latencyMs"], r["stopReason"])

# --- ConverseStream ---
s = brt.converse_stream(modelId=MODEL,
        messages=[{"role": "user", "content": [{"text": "Explain HNSW."}]}],
        inferenceConfig={"maxTokens": 600})
for ev in s["stream"]:
    if "contentBlockDelta" in ev:
        print(ev["contentBlockDelta"]["delta"].get("text", ""), end="", flush=True)
    elif "metadata" in ev:
        print("\n", ev["metadata"]["usage"])

inferenceConfig · additionalModelRequestFields

Inference parameter reference

OpenClose
ParameterWhere in ConverseOperational impactStarting point
temperatureinferenceConfigScales token-probability randomness. Low is near deterministic, high increases variety and drift.0 to 0.2 extraction, routing, tool use. 0.6 to 1.0 creative.
top_pinferenceConfig.topPNucleus sampling: restrict to the smallest token set whose cumulative probability reaches p.0.9 to 1.0. Tune this or temperature, not both. Some newer Claude models reject both.
top_kadditionalModelRequestFieldsSample from only the k most likely tokens. Not in the common Converse schema, and support varies by model family.40 to 250 where supported.
max_tokensinferenceConfig.maxTokensHard output cap. Truncates mid-sentence (stopReason: max_tokens), bounds worst-case cost and counts toward token-per-minute quota.Set to the realistic p99 output, not the model max.
stop_sequencesinferenceConfig.stopSequencesEnds generation when a string is emitted. Useful for structured or templated output and cutting rambling.Up to 4 on most models.
reasoning budgetadditionalModelRequestFieldsExtended thinking on supported models (for example {"thinking": {"type": "enabled", "budget_tokens": 4000}}). Adds output tokens and latency, and constrains temperature.Enable only for multi-step reasoning tasks.

Behavior to remember

  • BLOCK returns the blocked message. ANONYMIZE replaces with {EMAIL}-style tags and the call continues.
  • Version guardrails and pin the version in prod. DRAFT is mutable.
  • Grounding checks need the source passed as a guardContent block with qualifier grounding_source.

Streaming

  • Default is synchronous: chunks are scanned before release, adding latency.
  • Async mode lowers time-to-first-token but may emit text before it is flagged. Do not use it for hard PII blocking.
  • Guardrails are charged per text unit scanned, so scope filters to what you need.

        elif "returnControl" in ev:

            # sessionState={"invocationId": ..., "returnControlInvocationResults": [...]}
            ...

gotcha
  • idleSessionTTLInSeconds expires the session. After that the history is gone unless you saved it or use memory.
  • Lambda action-group timeout is the agent step timeout. Keep tools under about 25 s and push long jobs to Step Functions with a polling tool.
  • Lambda needs a resource-based permission for bedrock.amazonaws.com scoped to the agent ARN.

Framework notes

  • LangGraph: explicit state machine, checkpointers, human-in-the-loop interrupts. Best fit for production control flow.
  • LangChain: ChatBedrockConverse from langchain-aws, retrievers for Knowledge Bases.
  • CrewAI / AutoGen: role-based multi-agent. Budget turn limits and token caps, as loops multiply cost quickly.
  • Strands Agents: AWS open-source SDK, native Bedrock and AgentCore integration.

Production checklist

  • Hard caps: max iterations, max tool calls, wall-clock deadline per request.
  • Idempotency keys on every side-effecting tool.
  • Concurrency limiter per model to stay under Bedrock TPM/RPM quotas.
  • Graceful SIGTERM: finish or checkpoint in-flight runs.

langgraph_checkpoint.py
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.prebuilt import ToolNode, tools_condition
from langchain_aws import ChatBedrockConverse
from langgraph_checkpoint_aws import DynamoDBSaver   # verify args for your version

llm = ChatBedrockConverse(model="us.anthropic.claude-sonnet-4-5-20250929-v1:0",
                          temperature=0.1).bind_tools(TOOLS)

def agent(state: MessagesState):
    return {"messages": [llm.invoke(state["messages"])]}

g = StateGraph(MessagesState)
g.add_node("agent", agent)
g.add_node("tools", ToolNode(TOOLS))
g.add_edge(START, "agent")
g.add_conditional_edges("agent", tools_condition)
g.add_edge("tools", "agent")

app = g.compile(checkpointer=DynamoDBSaver(table_name="agent-checkpoints"))
cfg = {"configurable": {"thread_id": "tenant42:user7:conv9"}}
app.invoke({"messages": [("user", "Check order ORD-1042")]}, cfg)
app.invoke({"messages": [("user", "And its ETA?")]}, cfg)      # resumes thread

TableName: agent-checkpoints
BillingMode: PAY_PER_REQUEST

  - {AttributeName: pk, KeyType: HASH}    # thread_id
  - {AttributeName: sk, KeyType: RANGE}   # ts#step or checkpoint_id

  AttributeName: expires_at               # epoch seconds, GDPR/retention
  Enabled: true

pattern

Valkey in front, DynamoDB behind: read-through for the active window of messages, write-through checkpoints every graph step. Key by tenant:user:conversation to keep isolation obvious in IAM conditions and logs.

Converse toolConfig · tool_use loop

Tool use (function calling) with Converse

OpenClose
tool_loop.py
tools = {"tools": [{
    "toolSpec": {
        "name": "get_order_status",
        "description": "Look up shipping status for an order ID like ORD-1042.",
        "inputSchema": {"json": {
            "type": "object",
            "properties": {"order_id": {"type": "string", "pattern": "^ORD-[0-9]+$"}},
            "required": ["order_id"]}}}}],
    "toolChoice": {"auto": {}}}       # or {"any": {}} / {"tool": {"name": "..."}}

def get_order_status(order_id): return {"order_id": order_id, "status": "SHIPPED"}
REGISTRY = {"get_order_status": get_order_status}

messages = [{"role": "user", "content": [{"text": "Where is ORD-1042?"}]}]
for _ in range(6):                                    # hard iteration cap
    r = brt.converse(modelId=MODEL, messages=messages, toolConfig=tools,
                     inferenceConfig={"maxTokens": 1024, "temperature": 0})
    msg = r["output"]["message"]
    messages.append(msg)
    if r["stopReason"] != "tool_use":
        break
    results = []
    for block in msg["content"]:
        if "toolUse" in block:
            tu = block["toolUse"]
            try:
                out = REGISTRY[tu["name"]](**tu["input"])
                results.append({"toolResult": {"toolUseId": tu["toolUseId"],
                                               "content": [{"json": out}]}})
            except Exception as e:
                results.append({"toolResult": {"toolUseId": tu["toolUseId"], "status": "error",
                                               "content": [{"text": str(e)}]}})
    messages.append({"role": "user", "content": results})
print(msg["content"][0]["text"])
rules
  • Return every toolUseId from a turn in a single user message, including parallel calls.
  • Validate model-produced arguments against the schema server-side. Authorize with the caller's identity, not the agent's.
  • Return errors as status: "error" so the model can recover instead of crashing the loop.

chunk_embed_index.py
import boto3, json, hashlib
from opensearchpy import OpenSearch, RequestsHttpConnection, AWSV4SignerAuth

brt  = boto3.client("bedrock-runtime")
auth = AWSV4SignerAuth(boto3.Session().get_credentials(), "us-east-1", "aoss")
os_  = OpenSearch(hosts=[{"host": "abc123.us-east-1.aoss.amazonaws.com", "port": 443}],
                  http_auth=auth, use_ssl=True, connection_class=RequestsHttpConnection)

def chunk(text, size=400, overlap=60):             # tokens approximated by words
    w = text.split()
    for i in range(0, len(w), size - overlap):
        yield " ".join(w[i:i + size])

def embed(t):
    r = brt.invoke_model(modelId="amazon.titan-embed-text-v2:0",
        body=json.dumps({"inputText": t, "dimensions": 1024, "normalize": True}))
    return json.loads(r["body"].read())["embedding"]

def index_doc(doc_id, text, meta):
    for n, c in enumerate(chunk(text)):
        cid = hashlib.sha256(f"{doc_id}:{n}:{c}".encode()).hexdigest()   # idempotent
        os_.index(index="docs", id=cid, body={
            "text": c, "vec": embed(c), "doc_id": doc_id, "chunk": n, **meta})

Pipeline hygiene

  • Deterministic chunk IDs for upserts. Store a doc hash to skip unchanged files.
  • Deletion path: tombstone then purge doc_id from the vector store, or stale answers survive.
  • Attach ACL, tenant and source metadata at ingest, not query time.
  • Dead-letter queue for failed docs with the parser error attached.

Cost levers

  • Bedrock batch inference for bulk embedding backfills.
  • Truncate embedding dimensions (512/256) if recall holds in your eval.
  • Chunk dedup (near-duplicate boilerplate) before embedding.
  • Do not re-embed on metadata-only changes.

CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE chunks (
  id        uuid PRIMARY KEY,
  tenant_id text NOT NULL,
  doc_id    text NOT NULL,
  content   text NOT NULL,
  metadata  jsonb,
  embedding vector(1024)
);
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);
CREATE INDEX ON chunks (tenant_id);

SET hnsw.ef_search = 100;                      -- recall vs latency knob
SET hnsw.iterative_scan = relaxed_order;       -- pgvector 0.8+: keeps filtered queries full
SELECT id, content, 1 - (embedding <=> $1) AS score
FROM chunks WHERE tenant_id = $2
ORDER BY embedding <=> $1 LIMIT 8;

judge.py (custom LLM-as-judge)
import json
RUBRIC = """Score 1-5 for each: groundedness (claims supported by CONTEXT),
answer_relevance, completeness. Return ONLY JSON:
{"groundedness":int,"answer_relevance":int,"completeness":int,"reason":str}"""

def judge(question, context, answer, judge_model=JUDGE_MODEL):
    r = brt.converse(modelId=judge_model,
        system=[{"text": RUBRIC}],
        messages=[{"role": "user", "content": [{"text":
            f"QUESTION:\n{question}\n\nCONTEXT:\n{context}\n\nANSWER:\n{answer}"}]}],
        inferenceConfig={"temperature": 0, "maxTokens": 400})
    return json.loads(r["output"]["message"]["content"][0]["text"])

Production gotchas

The failures that show up after the demo works.

  • ThrottlingExceptionQuotas are per model, per region, in tokens-per-minute and requests-per-minute. Use adaptive retries, jittered backoff, a client-side semaphore, and cross-region profiles.
  • max_tokens burndownSome models reserve quota against maxTokens up front. Oversized caps throttle you earlier than real usage would.
  • Read timeoutsLong generations exceed the default boto3 read timeout. Raise read_timeout and stream.
  • Model ID driftModels are retired. Keep IDs in config, track deprecation notices, and rerun evals on every swap.
  • Embedding mismatchQuery and index must use the same model and dimensions. Changing either means a full re-index.
  • Stale KBIngestion is not automatic on S3 change. Trigger sync jobs and alarm on job failure and document counts.
  • Unbounded agent loopsCap iterations, tool calls, tokens and wall time per request. Alarm on outliers.
  • Shared-role sprawlOne role for all agents makes blast radius and audit useless. One role per agent, scoped to its resources.
  • Logging secretsPayload logging captures PII and credentials users paste in. Mask first, encrypt, restrict reads.
  • Region coverageFeatures (Guardrails options, AgentCore pieces, models) differ by region. Check availability before designing around one.
